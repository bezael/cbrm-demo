# cbrm-demo

> 🇪🇸 Un Issue de GitHub convertido en una PR verificada con el **Contract Based Review Method (CBRM)**, paso a paso y con cada artefacto en el historial. Es una demo mínima a propósito.

A small feedback API that takes **one** GitHub Issue to **one** verified Pull Request with the Contract Based Review Method:

```
Issue  ->  Contract  ->  Lane  ->  Verdict  ->  PR
          (criteria)   (harness)  (evidence)
```

You don't trust the agent's code because it looks right. You review it against a contract, and you read the verdict instead of the diff.

## Read it in this order

| Step | Where | What to look at |
|------|-------|-----------------|
| 1. Baseline | first commit | A Fastify + Vitest API with feedback items, and CI |
| 2. Lane | [`AGENTS.md`](./AGENTS.md) | Generated by `dominicode-harness-init`: the real verification commands (all run, with times), conventions and boundaries |
| 3. Issue | [Issue #1](../../issues/1) | "Let signed-in users vote on feedback", with the clarifying answers |
| 4. Contract | `specs/feedback-voting/` in PR #2 | `spec.md`, `plan.md` and `tasks.md` from `dominicode-sdd-creator`: every criterion with the command that proves it |
| 5. Verdict | [PR #2](../../pull/2) | Status, alignment and a criterion → evidence table. The diff is only worth opening where the verdict is red |

## Run it

```bash
npm ci
npm test            # Vitest
npm run typecheck
npm run lint
npm run dev         # http://localhost:3000
```

Authentication is a demo stand-in: the caller's id arrives in the `x-user-id` header.
